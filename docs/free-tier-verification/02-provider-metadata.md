# Task: enrich provider metadata for one provider

Fill the human-useful curated fields on a generated provider record so a later
reader (human or LLM) understands what the provider is and how to get access.

Work from the repository root. Set `PROVIDER` to the provider slug, for example
`groq`. If it is not given, ask for it before writing.

## Target file

`.agentone/providers/<PROVIDER>/<PROVIDER>.json`

This file is generated by `manage.py refresh_catalog` / `refresh_free`. The
fields listed below are curated and preserved across regeneration; everything
else is generated.

## You may edit only these keys

```text
description
setup_instructions
url
api_key_url
default_api_key
doc
litellm_prefix
wire
research_sources
```

Do not edit or remove `_generated_by`, `catalog_updated_at`, `sources`,
`model_count`, `provider`, `api_base`, or any other key. Do not touch model
files, the reviewed dataset in `.agentone/free/`, or the free-tier cache.
Never edit `docs/free-tier-research/`; it is legacy research.

## Research

1. Find the provider's official website, console/signup page, API docs,
   pricing/free-tier page and key-management page.
2. Confirm whether the API is OpenAI-compatible, which LiteLLM prefix applies,
   and whether any special headers are required.
3. Use official sources only. Add every URL you rely on to `research_sources`.

## Write

1. `description` — 1–3 factual sentences about the usable API and its free
   access. State standing free tier vs trial/credit gating when relevant. No
   marketing copy.
2. `setup_instructions` — one short numbered string with exact actions and URLs.
   Example style:

   ```text
   1. Create an account at https://api.airforce/signup/ (no card).
   2. Create an `sk-air-...` API key under Dashboard -> API Keys
      (https://api.airforce/dashboard/#api-keys).
   3. Point an OpenAI-compatible client at the provider's `api_base`.
   ```

   Keep it operational. Include an env var name only if it is documented.
3. `url` — main website or console URL. Add it if missing; replace it only if
   it is clearly wrong. Never use the API base as `url`.
4. `doc` — official API/reference docs URL, when available.
5. `api_key_url` — exact key-management URL, only when a user-specific key is
   needed.
6. `default_api_key: "public"` — only when the documented free path needs no
   user-specific key. Do not use it merely because getting a key is easy.
7. `litellm_prefix` — only when verified, e.g. `groq` or `openrouter`.
8. `wire` — only when verified. Include `wire_verified: "YYYY-MM-DD"` and only
   confirmed transports/headers. Otherwise omit the whole block.
9. Omit any field you cannot verify. Never write `null` placeholders.
