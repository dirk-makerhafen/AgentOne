# Free-tier verification tasks

One file per task. Point an agent at a single task file; each file is
self-contained and tells the agent everything it needs, including the rules,
the paths and the output shape.

| Task | File | Writes |
|---|---|---|
| Plan the next batch | [`01-plan-batch.md`](01-plan-batch.md) | nothing |
| Enrich provider metadata | [`02-provider-metadata.md`](02-provider-metadata.md) | `.agentone/providers/<provider>/<provider>.json` (allowlisted keys only) |
| Verify one provider's free tier | [`03-verify-free-tier.md`](03-verify-free-tier.md) | `~/.agentone/var/cache/free-tier/reviews/<provider>.json` |
| Audit one review | [`04-audit-review.md`](04-audit-review.md) | `~/.agentone/var/cache/free-tier/reviews/<provider>.json` |
| QA a batch | [`05-qa-batch.md`](05-qa-batch.md) | curated fields + review files only |

Typical order per provider: `01` → `02` → `03` → `04`, then `05` for the batch.
After the batches, a human runs `manage.py merge_free_reviews` (see below);
that merge is not an agent task file.

## Data layout

```text
.agentone/providers/<provider>/<provider>.json          generated provider record
.agentone/providers/<provider>/<model>.json             generated model record
.agentone/free/<provider>.json                          final reviewed dataset (command-written)
.agentone/free/index.json                               final reviewed index

~/.agentone/var/cache/free-tier/candidates/<provider>.json   generated free candidates
~/.agentone/var/cache/free-tier/candidates/index.json        generated free index
~/.agentone/var/cache/free-tier/reviews/<provider>.json      curated verdicts (agent-written)
```

Only `.agentone/free/` is versioned. The `free-tier/` cache is re-creatable dev
state outside the checkout (`refresh_free` writes `candidates/`, agents write
`reviews/`, `merge_free_reviews` reads both).

A free candidate carries:

```json
{
  "model": "kimi-k2-5",
  "model_name": "Kimi K2.5",
  "provider_model_id": "kimi-k2.5",
  "limits": { "rpm": 30 }
}
```

`model` is the canonical slug and the model filename; `provider_model_id` is the
exact string to send in an API call.

## Writable vs generated

Generated by `manage.py refresh_catalog` / `refresh_free`:

- `~/.agentone/var/cache/free-tier/candidates/`, including `index.json`
- `.agentone/providers/<provider>/<model>.json`
- every field of `.agentone/providers/<provider>/<provider>.json` except the
  curated allowlist below

Agent-writable:

- `~/.agentone/var/cache/free-tier/reviews/<provider>.json` (curated, no `_generated_by`)
- in `.agentone/providers/<provider>/<provider>.json`, only:
  `description`, `setup_instructions`, `url`, `api_key_url`,
  `default_api_key`, `doc`, `litellm_prefix`, `wire`, `research_sources`.
  The writers preserve these across regeneration.

Command-written:

- `.agentone/free/` — the single reviewed free dataset, produced only by
  `venv/bin/python manage.py merge_free_reviews --root .agentone`.
  It rebuilds the whole tree from `candidates/` plus `reviews/` in the free-tier
  cache, so never edit it by hand. Use `--dry-run` to validate without writing
  and `--strict` to make warnings fatal. Bad reviews block writing; unreviewed
  candidates are reported as warnings. The command never touches the database.
  `--candidates-dir`, `--reviews-dir` and `--output-dir` override those defaults
  (useful for isolated test runs).

Never edit `docs/free-tier-research/`; it is legacy research being retired.

## What counts as free

Include services that provide usable LLM API inference without payment, even
with quotas, RPM/RPD limits, limited free tokens, selected free models, account
registration or API-key registration.

Do not count: payment-required trials, one-time signup credits, promotional
credits with no standing tier, free web/chat without a free API, models free
only under a paid subscription, or services where payment is required to get API
access.

Discovery sources (leads only, never proof): Free-LLM, FREE-LLM-API-Provider,
freellms.org, the FreeLLMAPI monthly catalog, and OpenCode Zen's public docs.
Verify every claim against official provider docs, pricing/free-tier pages,
public `/v1/models` responses, or a safe live request.
