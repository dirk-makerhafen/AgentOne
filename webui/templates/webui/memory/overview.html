How memory works
Memory is the durable result of the reflection loop. Each node keeps: facts (memory.md), a playbook (reflection.md directives, injected into sessions when enabled), and an improvement ledger (improvements.md).

Improvements climb a capability ladder — memory fact → directive → skill → tool/script → harness fix. This UI never applies one for you. Filing a proposal creates a backlog work item; promoting it to ready (and implementing it) stays a human decision.

Source freshness comes from .memory_sources.md, written by the memory walker. The values here are as of the last walk; this page does not run the walker.
